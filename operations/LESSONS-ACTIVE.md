# LAiDIES active lessons

Keep this feed short. A judgment lesson leaves this file when a calibrated
mechanical fixture enforces it. Historical detail belongs in
`operations/painpoints-log.md`, not here.

1. Inspect the real desktop and 390/320 mobile result before claiming visual or UX quality. Integrity, hashes and route checks are not design review.
2. A building page must make its operated objects and visitor jobs obvious before opening anything. A masthead followed by generic cards is not a building experience.
3. Reuse current approved artwork before generating replacements. Never substitute CSS art, emoji, arbitrary circles, decorative lines or placeholder boxes for missing visual assets.
4. Use the locked vibrant 1990s candy palette and current exact references. Dark, muddy, beige, cottage-core, gold/plum-primary and generic glamour-cartoon work fails.
5. Text, controls, statuses and accessibility labels stay live. Generated signage, tiny baked labels and unverified embedded names are not functional authority.
6. Design for growth: books, issues, episodes, songs, classes and new features must expand without rebuilding the page or shrinking choices below usable size.
7. Preview before open: state what an object is, contains, does and whether it is ready. Quiet, held and unavailable controls must describe their real result.
8. Test the visitor outcome, not the route. Submit forms, inspect the result and console, exercise failure/recovery, and verify focus/history where relevant.
9. Keep exact maker and independent-review identities separate. A stale hash, overwritten screenshot or producer-authored PASS invalidates admission.
10. One writer owns a building lane at a time. Shared files have a separate owner; reviewers do not overwrite the candidate they are judging.
11. Pilot before batching. After two failed repair cycles, stop the composition or production method and correct the root cause.
12. Local, committed, pushed, deployed, publicly verified and published are distinct. Never promote one state from evidence for another.
13. A visual admission must cover the complete manifest asset set and exact reviewer receipts. A self-selected asset subset or unbound red-team/Opus label is not evidence.
