# Selected-song full catalogue playback

Local implementation; no public deployment. Existing KSVL_playTrack and KSVL_playTrackById callers resolve canonical admitted metadata, then start the full available TRACKS list rotated to the selected song. Catalogue order is preserved around that anchor, with one copy of each song, shuffle off and repeat off. No new programme inserts or held recordings are added. Legacy function name startSingle remains solely for caller compatibility. Dedicated mix/album/station entry points retain their selection behavior.

Natural completion keeps queue, position and ownership available, renders Finished and Play again, and persists original startTrackId in a catalogue context. Play again resets index0. Explicit Stop & close still clears queue/storage and hides player. Previous single-context saves remain readable. New saved records carry an optional validated finished flag; older records do not require it. Owner heartbeat uses the same saved payload; old-version tabs do not understand the new catalogue context, so release integration must update the shared player together and recheck mixed-version handling rather than claiming old tab compatibility.

Browser evidence: clicked actual NewsStand theme, verified selected song followed by Ep01 after seeking to end; used Previous to reach rotated tail, ended it and observed visible Finished/Play again; navigated to Radio and finished state persisted; Play again returned to NewsStand. Repeat one ended and replayed NewsStand. At320px finished bar remained visible and no horizontal overflow. Long full-catalogue listening was simulated by queue tests and seeking representative songs, not hours of playback. Pop-out transfer and concurrent-tab flow were not re-exercised in browser; queue persistence tests cover the data restoration mechanism. Public release and every-page trigger audit remain outside this preview.
