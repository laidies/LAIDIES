# SUNNYVAiLE High — the classes (how to actually USE the tools)

**Ali's idea, 2026-07-22:** *"how to actually use the tools effectively. e.g. what is the
difference between a regular chat, code, cowork etc — what are routines, what is a session,
what is an artifact etc etc… i think those are like the classes we should have in the high
school. that is too much for just text."*

## The split this resolves
| | LIBRAiRY | SUNNYVAiLE High |
|---|---|---|
| **Job** | Look it up | Watch how it's done |
| **Form** | Reference textbooks — pull one down, read the page you need, slide it back | Classes, video-led, one skill each |
| **Owns** | What a word means · what a tool is for · sourced answers | How to actually operate the thing |

This does **not** break [[hundred-ones-textbooks-not-courses]]. That rule bans *courses* in the
syllabus-and-attendance sense, because LAiDIES is for women with no time. A class here is a
short demonstration you watch once — not homework.

**The test:** if a reader could get it from a paragraph, it's a book. If she needs to SEE it
happen, it's a class. "What is a token" is a book. "What is an artifact" is a class — you
cannot read your way to understanding one appearing beside your chat.

## The material — operating concepts nobody has words for
People are handed these interfaces with no map. The vocabulary exists but is never taught:

- **The modes** — regular chat vs code vs cowork/agent mode. What each is FOR, and the tell
  that you are in the wrong one.
- **A session** — what it is, when it ends, what carries over and what does not.
- **An artifact / canvas** — a thing that appears beside the chat and can be edited, versioned,
  kept. Why this is different from text in a reply.
- **A routine / scheduled task** — the tool acting without you sitting there.
- **A project / space** — a container with its own files and standing instructions.
- **Memory** — what persists between sessions, where to see and edit it.
- **Connectors** — reaching your Drive, mail, calendar. What access is really granted.
- **Skills / plug-ins / extensions / MCP** — bolt-on capabilities, and what to ask before
  enabling one.
- **Context** — why it forgets, why a long chat degrades, when to start fresh.

## Proposed class list (draft — not approved)
1. **The Four Doors** — chat vs code vs cowork vs voice, and which to walk through
2. **What a Session Is** — and why your long chat got worse
3. **Artifacts** — the thing beside the chat that you can keep
4. **Set It Once** — memory, custom instructions, and being known
5. **Projects** — when a container beats a conversation
6. **Routines** — making it work while you are asleep
7. **Connectors** — plugging it into your actual life, safely
8. **Skills & Plug-ins** — bolting on capability, and what to ask first

## Why video, specifically
Each of these is a **two-minute screen recording** and near-useless as prose. "Here is where
memory lives, here is how to edit it" shown once beats a page of description. Confirms the
earlier note that some 101s want video — but this material is video-FIRST, not a text book
with a clip attached.

## 🟢 Why this is the CHEAPEST thing we make
**Ali, 2026-07-22:** *"because we don't need characters or something, hopefully something that
is easiest to create videos for."*

Correct, and it is the strongest production argument for doing these next. A screen recording
has **none of the failure classes that have cost us the most**:

| Episode art fails on | A class recording |
|---|---|
| likeness drift, invented faces | no people at all |
| heroine outfit continuity | no heroine |
| anatomy — missing limbs, bad hands | nothing drawn |
| invented backgrounds, mashups | the real interface |
| period accuracy, wrong-age portraits | n/a |
| comic style lock, saturation, generation mixing | n/a |

Production kit is: **screen capture + voiceover + a title card**. That is it. Compare with the
22-frame batch that came back ~7 usable.

It is also more honest for the subject — an *illustration* of an artifact teaches less than the
artifact actually appearing on screen.

## ✅ THE FRAME — DECIDED 2026-07-22
**Ali:** *"i think the classroom is the wrapper. the classroom has the name of the class on it
and you hit play on the TV that is on the stand and then that goes to big screen or something."*

**The classroom is the wrapper; the TV is the portal.**

1. You arrive in a **1999 classroom**. The **name of the class** is displayed in the room.
2. A **TV on a rolling AV stand** sits at the front — the wheeled-in cart, the specific 90s
   signal that you are not doing real work today.
3. **Hit play on the TV.** It expands to full screen and becomes the screen recording.

This resolves the 1999 tension without compromise: the town frame holds completely, the modern
software lives *inside the television*, and the transition is the whole joke. Nobody has to
pretend 2026 software looks like 1999.

**This is the reusable template for every class** — one classroom, one sign, one cart. Only the
class name and the recording change.

⚠ Mechanically close to the Chick Flicks Screening Room player ([[screening-room-episode-player]]),
but a DIFFERENT register — that is VHS movie night, this is the AV cart. Reuse the pattern
(click a device, it goes full screen), not the chrome.

⚠ Real UI recordings date fast — but they are cheap to RE-SHOOT, which is the point.
**Keep each class short and single-topic** so one UI change cannot invalidate a whole lesson.
Eight two-minute classes survive a redesign; one sixteen-minute class does not.
