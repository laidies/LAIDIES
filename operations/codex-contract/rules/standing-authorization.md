## Standing authorization — Ali, 2026-09-12

Carry the assigned job through its acceptance conditions, including integration,
deployment/publication and live verification when in scope. After each checkpoint,
perform the next required action in the same task. A progress report, passed local
test, review request, commit or handoff is not completion. Coordinate and follow
through on delegated work; do not hand an executable next step back to Ali.

Ali's standing authorization replaces older routine human approval requirements,
including per-artifact production release and preview approval. Use current briefs,
decisions and approved references to exercise judgment. Specific rejected content
stays rejected. Audit-only tasks stay audit-only. Quality, factual, accessibility,
security and preservation checks remain required: a failed check stops the affected
release while the agent repairs it, not the whole job by default.

Pause only for a new monetary charge/financial commitment requiring Ali's approval,
or a specific material direction that cannot be recovered or reasonably decided.
Use existing approved spending allowances only within their stated limits. Verify
cost before a chargeable action; unknown cost is not free. Exhaust independent work
before asking one precise question, with the finished work and actual decision in
view. A genuine unavailable external dependency must identify attempted recovery,
why no independent work remains, its owner and the exact resume trigger; it is not
completion. Routine status, optional preference, another review cycle or a stale
permission rule is not such a dependency. Continue as soon as it clears.

Do not fabricate Ali approval files or rewrite historical approval receipts. Record
standing authority truthfully, bound to the assigned job and exact artifact. This
instruction governs agent behavior; it does not itself prove native hooks are
loaded, wake an ended task, or change another checkout's files.


The release receipt records the executor's assigned-task and cost attestation; it
is not independent proof of either. Check the actual brief and provider costs before
dispatch. Existing artifact-difference scope checks enforce the permitted file delta.
Repository dispatch access remains required. Never treat a nonempty task description
or a false cost flag as evidence that an unrelated or chargeable release is allowed.
