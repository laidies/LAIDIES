# AI Fundamentals 101 — visual teaching plan

**Status:** SPECIFIED — Introduction through Chapter 3 rendered as a local
review proof; no visual or book admitted
**Owner:** Library
**Applies to:** the complete nine-chapter AI Fundamentals 101 successor and its
current Introduction-through-Chapter-3 review proof

## Governing rule

Visuals are part of the explanation. Each one must reduce the reader's mental
work by making a relationship, sequence, comparison or failure path visible.
No visual is admitted because a page looks empty or because every chapter is
expected to have one.

Technical labels, arrows, legends and captions are deterministic editable
layers. Illustrative art may carry the Library's approved visual language, but
it cannot invent the technical relationship or contain generated lettering.
Every visual has an equivalent text explanation and remains understandable
without colour.

## Planned teaching visuals

| Location | Form | Named teaching job | Required visible relationship | Text equivalent |
| --- | --- | --- | --- | --- |
| Introduction | Layered system map | Stop the word “AI” from collapsing the whole arrangement into one object | person and goal → product → supplied information/instructions → model and physical compute → optional tools → output/action → human consequence | The adjacent prose names every layer and says exact implementations vary. |
| Chapter 1 | LAiDIES Closet classification visual plus five-axis map | Show why several apparently conflicting AI labels can all be true | one familiar item carries several non-exclusive properties; one AI product is then classified by job, modality, method, breadth and access, with agentic operation kept separate | Prose explicitly ends the clothing analogy before it can distort the technical mechanism. |
| Chapter 2 | AI-system cutaway | Put the model in its correct place behind the product interface and make physical infrastructure visible | laptop interface → product software → network → server/chip/model → presented result → human checkpoint; local and remote variants remain possible | The worked email case names the role of product, model, input, output, compute and people. |
| Chapter 3 | Training loop plus training/inference comparison | Show how repeated measured adjustment shapes a model, then separate that process from current use | selected examples → current model → output → measured miss → parameter adjustment → repeat → separate evaluation; inference uses the resulting model without normally changing its parameters | Prose explains objective, loss, parameter, generalisation and the time boundary of training knowledge. |
| Chapter 4 | Working-information diagram | Distinguish context, context window, session, memory and retrieval | what is visible in the interface; what is supplied to the model for one step; what can persist; what can be fetched; what never entered working context | Prose warns that visible, stored, retrievable and model-supplied are not synonyms. |
| Chapter 5 | Permission-bound tool/action diagram | Show what APIs, connectors, tools, routing and MCP add around a model | request → model suggestion or structured tool call → permission boundary → tool execution → returned observation → product result | Ordered steps name which component performs each action and distinguish generation from execution. |
| Chapter 6 | Agent/workflow loop | Make multi-step execution and human control points visible | goal → plan/route → action/tool → observation → update → stop/continue, with explicit permission, approval, recovery and stopping points | Prose explains that a loop does not guarantee autonomy, correctness or responsibility. |
| Chapter 7 | Failure-location diagnostic | Help readers locate why an AI-assisted result failed | model, data, context, retrieval, tool, interface, workflow and human/institutional decisions route to different evidence and repairs | A decision list separates hallucination from other failure families and scales review to consequence. |
| Chapter 8 | Data journey plus access/control comparison | Make governance a lifecycle rather than a privacy warning | collection → current use → storage → retrieval → sharing → possible training use → retention/deletion; open source, open weight, source available and closed remain distinct | The confidential-document case supplies the same decision route in prose. |
| Chapter 9 | Deployment ripple map and lifecycle strip | Connect one AI system to changing work, resources, institutions and public claims | task → people → organisation → labour/resources/access/standards; deploy → monitor → update → correct → retire | The dated-claim case separates evidence, institutional framing and forecast. |
| Concept Index | Mini relationship map | Let a lookup reader see where one term belongs before jumping to a chapter | grouped concept families connect to the nine chapter mechanisms; no glossary wall | Each index entry retains a one-line meaning, chapter link and system connection. |

## Current rendered proof

The Introduction-through-Chapter-3 proof renders five deterministic teaching
visuals: the whole-system chain, Closet/five-axis classification map, AI-system
cutaway, training loop and training-versus-inference comparison. Labels are
HTML/SVG text rather than generated lettering. This proves the component
system and responsive treatment; it is not approval of final art direction or
authority to publish. Chapters 4–9 remain planned, not rendered.

## Visual acceptance

1. The maker states the question each visual answers and why prose alone is
   insufficient.
2. Every arrow, containment, sequence, loop and boundary is factually correct
   and bound to the chapter's source evidence.
3. A newcomer can explain the relationship from the visual without reading a
   hidden maker note and without inferring meaning from colour alone.
4. Labels and arrows remain legible in the actual desktop and mobile reader at
   native size and 200 percent zoom; horizontal diagrams recompose rather than
   shrink into unreadable posters.
5. Caption and equivalent prose preserve the lesson when the image is absent.
6. The exact rendered pixels receive maker inspection and role-distinct visual
   judgment under the shared visual-media gate before full-book admission.

## Non-goals

- No decorative clip art, generic circuitry, floating robot heads or stock
  “woman using AI” scenes.
- No visual quota and no repeated card template.
- No provider logos where a system role is the actual lesson.
- No generated technical lettering.
- No animation unless motion is the only clear way to teach change over time;
  the book must still provide the static and text equivalent.
