## What the reader should finish with

A usable plan for a 90-minute community workshop: a checked cost table,
90-minute agenda and invitation draft. The reference fixture is deliberately
small enough to expose unnecessary research, reviews or scope expansion.
A second, genuinely difficult case is required before recommending Max.

## Exact starting material: workshop-brief.md

```text
Event: Getting Started with AI, a fictional community workshop.
Audience: 12 adults who have not used an AI assistant before.
Date and location: not confirmed; leave clearly marked placeholders.
Length: 90 minutes, including a 10-minute break.
Budget ceiling: CAD 350, excluding no items; all supplied costs include tax.
Room: CAD 120 total.
Refreshments: CAD 8 per attendee for 12 attendees.
Printing: CAD 2.50 per attendee for 12 attendees.
Reserve: 10% of the room, refreshment and printing subtotal.
Do not charge attendees. No paid AI subscriptions are required.
Participants may use their own available free assistant. Do not promise a
particular model, upload feature or account allowance. Include a paired,
paper-based fallback so nobody needs to create an account during the session.
Use invented practice details, not participants' private documents.
Invitation: 120 words maximum; plain, welcoming, no exaggerated claims.
Deliverables: costs.csv and workshop-pack.md; no website, logo or slide deck.
```

These are ordinary proposed filenames, not special automatic context files.
Attach/paste them in chat; in a local agent project, name the exact copied
input path and authorized output folder. Do not imply a web upload grants
access to the original computer folder.

## Exact reusable project rule: bounded-work

```text
Use the supplied task materials as the source of truth. Ask only for missing
information that prevents a useful, correct result; otherwise label a placeholder.
For this fictional workshop fixture, use the supplied facts without web research.
Create only the requested outputs. Preserve original inputs.
Check arithmetic, completeness, specified length and internal consistency.
Repair concrete failures and rerun the affected checks. Stop when all required
checks are satisfied; do not add broad audits, reviewers or unrelated improvements.
If a check cannot be completed, report the gap instead of claiming success.
Do not buy, send, publish, delete, install tools or change connected accounts.
```

Placement: project instructions in a supported chat project; `AGENTS.md` for

proposed rule text, not an installed file or a universal instruction hierarchy.
In ordinary one-off chat, paste it with the task. Do not add the same rules to
every layer. Technical restrictions, permissions and approval controls remain

## Exact initial prompt: complete job

```text
Using workshop-brief.md and the bounded-work rules, create costs.csv and
workshop-pack.md for this fictional workshop.

costs.csv: item, calculation, amount_cad; include subtotal, reserve, total and
budget remaining. Quote CSV fields when needed. Do not hide the reserve inside
another cost or apply it to itself.

workshop-pack.md: a 90-minute agenda with durations including the break, a
120-word-or-shorter invitation with date/location placeholders, and a short
host checklist. Include the no-account fallback and privacy instruction.

Use calculation tools if available; otherwise show the arithmetic and identify
that limitation. Verify the total duration, arithmetic, invitation word count
and every requirement in the brief. Do not perform external research for this
supplied-fact exercise. Do not create additional deliverables or review teams.

Return links to actual files if this session can create them. Otherwise return
the complete CSV and Markdown contents, clearly labelled as text rather than
downloadable files. End with checks performed and anything still unresolved.
```

## Model-specific variants to compare

Keep the source fixture unchanged. Record product, exact model/version, effort,
execution mode, plan, platform, relevant tools and checked date for every run.

- **Luna / low or Light, where exposed:** first ask only for the complete
  `costs.csv` output with the arithmetic check. Then provide that checked output
  with the brief for the agenda/invitation stage. This staged trial tests a
  narrower contract; compare its total interaction cost with the complete-job
  prompt, not just the first cheap response.
- **Terra / Medium:** use the complete-job prompt unchanged. Test Light on the
  same inputs before concluding Medium is worth more usage.
- **Sol / Medium:** use the complete-job prompt unchanged, then compare Light.
  No extra reviews are requested merely because a flagship is selected.
- **Claude:** use the exact documented model/effort recipe in the Claude packet.
  For Fable's high-effort trial, compare a bounded check/stop instruction with
  the otherwise identical base prompt. No invented claim that every Fable run
  over-reviews. Other model comparisons must retain their own supported controls.
- **Free route:** use the actually available model without claiming access to a
  paid picker. Paste the inputs if attachments are unavailable. Complete text
  outputs are a legitimate limited fallback, not equivalent to tested file
  creation or autonomous computer work. Record interruptions and reset limits.

The staged Luna run changes workflow as well as model, so it is a practical
recipe comparison, not an isolated model benchmark. For a model-only comparison,
hold prompt, tools, inputs and acceptance checks constant. To isolate effort,
hold model constant. Change the prompt only in a separately identified trial.
