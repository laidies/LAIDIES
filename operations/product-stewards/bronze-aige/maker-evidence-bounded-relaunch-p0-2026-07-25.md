## Failure found in the exact artifact

The first fresh artifact omitted `content/episodes/issue-04.json`. Source behaviour and source tests passed because the runtime path was constructed dynamically, but the static dependency crawler could not discover it. The product safely fell back to evergreen copy, yet the newest prompt could never become current in the packaged site.

The repair is an explicit admitted map of issue 1–4 JSON paths, used for both runtime admission and static packaging. The rebuilt artifact contains issue 4 and passes the same source/artifact suites. This is a reusable rule: dynamic content paths require explicit package-visible dependency admission and exact-artifact verification.
