- **Product:** LAiDIES Homepage & Town Entry.
- **Complete scope:** `/`, `/start-here.html`, first/current/return hierarchy,
  conditional news, map/directory/orientation handoffs, global navigation as

  truthful useful route, sees current content only when admitted, retains a
  useful fallback, and is never led to believe a route visit proved a

  episode/news authorship; platform/global brand decisions; account/reward
  architecture owned elsewhere; deploy, campaign or announcement.

## Proposed direction

Build a **truth-first semantic threshold** before a visual migration:

1. one authoritative readiness/current-content projection;
2. one primary newcomer action, current learning/news prominence and quieter
   optional exploration hierarchy;
3. deliberate four-state visitor behavior without false identity/rewards;
4. deterministic accessible UI with current candy rhythm; and
5. visual-system application only after the Brand & Experience championship.

No external tool, plugin or paid service is proposed. The limiting factors are
shared authority, admission evidence and exact release binding, not missing
software. No installation or spending approval is requested.

## Executable craft contracts

### TE-P0-1 — readiness projection

Produce one machine-readable record for every promoted route:

`product_id, owner, exact route, visible label, current disposition,
limitation, evidence timestamp, freshness deadline, exact artifact/deployment
identity, fallback route, correction/withdrawal state`.

Missing, stale, held or artifact-mismatched records fail closed. The homepage
consumes this projection; it does not duplicate owner prose. Fixtures cover
all current promoted cards, map routes, hero/current routes and the seventeen
directory destinations.

### TE-P0-2 — four visitor states

Run one source and browser matrix for:

- first-time;
- returning without Card;
- device-local Card; and
- verified account-backed Resident.

Test first→return, visitor→Card, Card→account, expiry/sign-out/revoke,
storage denial/corruption, second tab/device, conflict and deletion. Rule every
tour/charm/FAiRY Play/ritual/resume write as local keepsake, authoritative
event, held behavior or rejected legacy. Route arrival cannot become a
learning/reward event by implication.

### TE-P0-3 — shared semantic tests

Replace private DOM-shape assertions with public semantics:

- Start Here and homepage can reach the current Centre route;
- the Centre exposes all required named destinations and limitations in its
  own current contract;
- data failure leaves an accessible named fallback;
- close/Escape returns focus; and
- route arrival is not downstream completion.

The homepage test must not prescribe the Centre owner's internal `hidden`
attribute, layout or component name.

### TE-P0-4/5 — hierarchy and current content

Build an isolated semantic prototype with:

1. practical promise;
2. exactly one primary newcomer destination action;
3. current episode plus The Breaking/The Daily only when admitted;
4. one useful-thing route;
5. compact purpose chooser;
6. optional town exploration; and
7. guarded Card/newsletter depth.

Preserve current vibrancy and object specificity. Do not select a sitewide
rendering style. The Breaking collapses on a clear day; The Daily opens the
exact explanation; corrections/retractions invalidate every cached consumer.
Compare incumbent plus two materially different hierarchy challengers when
the primary-path decision remains consequential. Red-team and blind-score
them before Ali sees a finalist.

### TE-P0-7/8 — admission scenes

For each desktop, 390px and 320px candidate, and at real 200% zoom:

- first-viewport comprehension and named choices;
- keyboard/visible-focus/menu/Escape/focus return;
- landmarks/headings/skip route/announcements/target size;
- VoiceOver + Safari and representative keyboard browser;
- reduced motion, audio and image/font/script/data failure;
- no-JS Start Here and core link fallback;
- hero/map responsive asset crop/alt/fallback; and
- LCP/CLS/INP plus transferred bytes on representative mobile conditions.

### TE-P0-9 — measurement

Approve only bounded properties:

`route_key, surface, viewport_bucket, visitor_scope_without_identity,
route_disposition, error_category, candidate_id`.

Prohibit email, lookup/query text, prompt/form content, account/user
identifier, local-storage values, postcard text and raw replay material. Pair
aggregates with a small consentful comprehension sample. Click-through alone
cannot win.

## Measurement and learning

- **Baseline:** distinctive current page, named local episode-recovery pass,
  partial navigation/handoff evidence, no complete four-state/human/native/
  performance/public admission.
- **Success:** accurate first-glance comprehension, correct admitted-route
  choice, useful quiet/failure behavior, zero false receiver/reward/current
  claims, accessible completion and voluntary return.
- **Failure:** stale current cue, held destination promoted broadly, token/local
  state presented as identity, route visit presented as completion/reward,
  query/email leakage, focus loss, poor mobile performance or style drift.
- **Review:** after exact local candidate; after authorized public interval;
  per episode/news/destination change; before any campaign.
- **Dossier updates:** state, backlog, map, evidence, independent verdict,
  decision receipts and qualifying learning after every cycle.
