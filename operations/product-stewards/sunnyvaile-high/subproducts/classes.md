# Classes — Curriculum & Production subchampion

**Status:** ACTIVE OWNER CONTRACT — catalogue and all proposed tapes remain
subject to the current High admission state.

## Job

Own every SUNNYVAiLE High class from idea intake through current research,
instructional design, narration, animation, screen demonstration, guided
practice, accessible media, admission, measurement, correction and reshoot.
The class must turn understanding into observable skill. It is not a second
episode, a narrated book or a generic product tour.

## Mandatory re-entry for every new class idea

Before proposing a title, syllabus or script, read:

1. `operations/product-stewards/OWNER-ENTRY-CONTRACT.md` and run
   `node scripts/check-product-stewards.mjs --owner-entry classes`;
2. `operations/product-stewards/LEARNING-CONTENT-STANDARD.md`;
3. `operations/checklists/learning-content-intake-template.md`;
4. `operations/product-stewards/learning-content-ecosystem/concept-map.md`;
5. `operations/research/laidies-learning-system-content-audit-2026-07-25.md`;
6. `operations/research/high-school-class-list-proposal.md`;
7. `content/site/high-classes.json`;
8. the relevant episode canon/opportunity scan;
9. the relevant LIBRAiRY 101 owner/passages; and
10. the High `OPERATING-SPEC.md`, state and backlog.

Copy the intake template into this dossier for the candidate. Reconcile the
idea against existing classes and neighboring learning surfaces before
scripting. The intake record must identify:

- the canonical concept owner;
- the class's observable skill and modality advantage;
- what Concepts/LIBRAiRY explains instead;
- what an episode introduces instead;
- the real current interface or mechanism that must be shown;
- the practice, failure, feedback and transfer evidence;
- volatile facts and the source/recheck/reshoot trigger; and
- named cross-product handoffs.

## Trigger handling

The subchampion reopens on:

- an explicit new-class idea from Ali;
- `class_impacts[]` selected by an episode opportunity scan;
- a new or materially changed product interface/capability;
- a correction or freshness expiry affecting an existing class;
- learner evidence showing a comprehension or transfer gap; or
- a dependency decision from Library, Episodes, Tools, Games or NewsStand.

An episode impact is a review trigger, not an instruction to manufacture a
class. Prefer, in order: link the existing class; correct it; update it; extend
it; create a new class only when a distinct observable skill remains.

## Cross-product handoff

When a class candidate exposes a missing or incorrect durable explanation, the
Classes owner records a Concepts/LIBRAiRY handoff rather than teaching a
competing canonical definition. When an episode creates a useful class
candidate, the episode owner supplies the ruled concept, source and intended
learner need; the Classes owner independently decides the practical class job.

The product dossier and intake card are the message bus. A chat response is
never the only record.

### Weekly Episode Engine boundary

The permanent Weekly Episode Engine task is
`019f9f7c-f03a-7ec1-a776-d60b57210322`. It owns each episode's lifecycle and
runs the episode opportunity/impact scan.

For a possible class, the Episode Engine sends Classes a structured
`class_impacts[]` proposal containing the ruled episode concept, source
authority, intended learner need, proposed practical skill, timing/freshness
risk and relevant episode evidence. Receipt of that proposal is a
**CAPTURED review trigger**, not a class commission.

Classes then completes the learning-content intake/complement card, reconciles
the concept map and current inventory, and independently decides **link,
correct, update, extend, create or decline**. A new class is warranted only
when a distinct observable practice skill remains and class media can
demonstrate, diagnose, give feedback and test transfer better than the episode
or LIBRAiRY owner. Classes must not turn the episode into a duplicate class or
create competing canon.

## Admission boundary

No idea, row, script, video, local route or completed intake card is a live
class. Admission still requires the High operating spec and learning ledger,
current sources, independent accuracy/instructional review, unfamiliar-learner
evidence, accessible media and exact public verification.
