# SUNNYVAiLE High Building — launch deep dive

**Status:** REPORT READY — evidence-based building assessment; not an implementation, learning-content approval, reward verification, commercial approval, or public-verification claim.

## Intent

SUNNYVAiLE High is the applied-learning building: Chick Flicks tells/shows the episode, the LIBRAiRY supports retrieval, and the High is where someone sees a task performed, practises judgment and receives feedback. Its schoolhouse setting—AV cart, Pop Quiz, report card, yearbook, 101 shelf and Book Fair—can make practice memorable, provided it does not reduce learning to grades, collectibles or a busy progress game.

## Learning/content quality and accuracy

The building's promise is stronger than “take a fun quiz.” Every class/quiz needs a named learning objective, current source packet, mechanism explanation, practical transfer, explanation of feedback, and an explicit boundary on any analogy. The standing publication standard applies: no simplified/outdated AI claim merely because it is familiar; changing claims need primary-source-first verification and as-of dates.

Current evidence is mixed. The Pop Quiz has a reasonably concrete local interaction model (episode choice, scoring, explanations, best-score/reward hooks). Try-On is a useful external benchmark because it does not fake an AI result. But the current classes dependency is a launch **FAIL**, and the broader QA matrix calls quiz-to-reward journeys only PARTIAL pending duplicate/local/account-sync and learning-value checks. A rendered quiz cannot certify valid assessment or transfer.

## Visual/brand and UX

The schoolhouse objects create a coherent applied-learning world: a real hallway, Pop Quiz desk, AV-cart classes and Book Fair are more distinctive than a generic LMS. The building correctly articulates its relationship to Chick Flicks and LIBRAiRY. Risks are density and false permanence: corridor panels, transcript, superlatives, books, quiz, clips and Fair can expose too many systems before a newcomer understands one useful task.

The right visual standard is object-world clarity: one primary learning route, clear practice/feedback, supportive optional depth, and no dashboard-like reward mechanics. It must feel encouraging, not evaluative or exclusionary.

## Accessibility, mobile and performance

The code includes responsive corridor layout and reduced-motion treatment, but those are implementation facts, not a complete experience verdict. The launch matrix shows the High route/classes promise failed because the class JSON 404s. No bounded evidence establishes full keyboard and screen-reader behavior across corridor panels, report-card table, quiz selection/results, Book Fair redemption, focus return, touch targets, network failures, or real-device Safari. Field Core Web Vitals are also unmeasured.

## Persistence, rewards and backend truth

Report Card/yearbook data is derived from quiz-related local state, while intended account persistence relies on broader Identity/Rewards/Supabase contracts. The Book Fair uses butterfly clips, which require one authoritative grant/display/spend/refund ledger across quiz, Closet and Fair. The whole-site matrix records only a partial local foundation and requires balance, duplicate, refund, insufficient-funds, account sync and fulfilment proof.

This produces a strict product rule: the building may celebrate an activity completed on this device, but must not say it is permanent, cross-device, or redeemable unless the relevant authoritative lifecycle has passed. The existing “Stocking soon” Book Fair disabling is an honest interim state, not fulfilment.

## Analytics gap

Plausible/Clarity embeds do not establish learning measurement. The building needs an approved, privacy-safe event contract for route selection, class start/complete, quiz start/explanation/retry, record view, Book Fair unavailable/redemption and errors. Do not log answer content, sensitive learning inferences, personal card fields or a public ranking. Pair aggregated signals with qualitative comprehension/transfer evidence; raw completion rate cannot prove learning.

## Improvements, upkeep and revenue

First restore the core class route and prove one complete teach → practise → explain → continue vertical slice. Maintain content by scheduling source/currency review as AI products change, reviewing question validity after real evidence, and removing stale routes rather than leaving decorative inventory. Only then test supportive, opt-in mastery guidance from authoritative records. Revenue comes last: a Book Fair/print offer can be delightful if it has real stock and support value, but must not gate core learning, convert quiz scores into pressure, or promise an unfulfilled reward.

## Verdict

SUNNYVAiLE High is **SPECIFIED** as a strong learning-building concept with some **BUILT LOCALLY** quiz/record mechanics, but its promoted classes route is currently **FAIL** and reward/account truth is incomplete. Launch work should repair or hide the broken class promise and verify one full learning vertical slice before adding curriculum volume, gamification or commerce.
