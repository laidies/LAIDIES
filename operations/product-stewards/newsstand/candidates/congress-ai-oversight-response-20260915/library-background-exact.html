14.1 — What Makes an Agent Different From a Chatbot

A chatbot answers questions. You ask, it responds. One exchange. Done.

An agent does work. It takes a goal, breaks it into steps, uses tools, evaluates its own progress, and keeps going until the job is done — or until it gets stuck and asks for help.

The three things that make something an agent rather than a chatbot:

  1. Tools. The system can do things beyond generating text — search the web, read files, send messages, execute code, interact with other software.
  2. A loop. Instead of one-shot (question → answer), the system runs in a cycle: think about what to do → do it → observe the result → decide what to do next → repeat. It can take multiple actions in sequence without waiting for you to tell it each step.
  3. State and memory. The system maintains awareness of what it's already done, what it's tried, what worked, and what didn't — within a task and (sometimes) across tasks.

A chatbot generates text. An agent generates text and takes actions and evaluates its own work and iterates until a goal is reached.

By the end of this chapter, you will be able to:

  • Explain what makes an agent different from a chatbot (tools + memory + a planning loop)
  • Describe the agent loop: perceive → reason → act → observe → repeat
  • Understand how "tool calling" works — how a model triggers real actions
  • Explain what MCP (Model Context Protocol) is and why it standardises how agents connect to tools
  • Describe the difference between single agents and multi-agent systems
  • Understand where agents are now (2026) — what they can reliably do, and where they still struggle
