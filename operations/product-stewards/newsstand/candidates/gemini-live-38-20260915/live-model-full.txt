L84: # Gemini 3.8 Live
L85: 
L86: Gemini 3.8 Live is the default option for most low-latency voice agent experiences and real-time dialogue without reasoning-induced delays. It supports interleaved reasoning, asynchronous function calling, full session client content updates, and built-in audio streaming.

L104: id_card Model card  | cite23†Model card†deepmind.google L105: ## Migrating from Gemini 3.1 Flash Live
L106: 
L107: Gemini 3.8 Live delivers ultra-low latency audio-to-audio interactions and expands support for asynchronous workflows. When migrating from `gemini-3.1-flash-live-preview`, review the following updates:
L108:   * Model string: Update your model string from `gemini-3.1-flash-live-preview` to `gemini-3.8-live`.
L109:   * Thinking level: `thinking_level` is not supported for `gemini-3.8-live`. Omit `thinking_level` (or `thinking_config`) from your session setup.
L110:   * Asynchronous function calling: Async execution (`behavior: NON_BLOCKING`) is now the default function calling mode. You can still use synchronous blocking mode for backwards compatibility by setting `behavior: BLOCKING` on your tool declarations. Function scheduling (`SILENT`, `WHEN_IDLE`, `INTERRUPTED`) is supported.
L111:   * Client content updates: `send_client_content` is supported throughout the entire session lifecycle with explicit roles (`user` or `model`). Setting `turn_complete=true` unconditionally interrupts active model generation. If you send content without `turn_complete`, the server waits for subsequent messages before responding.
L112:   * Proactive audio: Proactive audio is now permanently enabled. Setting `proactive_audio: false` returns an error.
L113:   * Affective dialogue: Affective dialogue is removed from the API. Remove any `enable_affective_dialog` configurations from your code.
L114:   * Turn coverage: Defaults to `TURN_INCLUDES_AUDIO_ACTIVITY_AND_ALL_VIDEO`. Video frames are sent to the model by default, so only send frames when needed to manage context and cost.
L115:   * Response modalities: Audio is the supported response modality. Enable output audio transcription if your application requires a text transcript.
L116: For a feature comparison across all Live API models, see the cite24†Model comparison table.
