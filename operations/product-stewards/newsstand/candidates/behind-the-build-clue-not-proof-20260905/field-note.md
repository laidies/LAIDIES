# What did “done” actually do?

One lesson I’ve learned while building LAiDIES: when an AI assistant says a task is finished, ask **what has it actually checked?**

Let’s use a fictional example. You ask an assistant that can work with files to prepare a workshop handout and share it with your team. It creates the document and reports, “Done!”

Lovely. But can your colleague open it?

If the assistant checked only that the file exists, it has established that a document was created. Sharing is a separate part of the job: the link needs to lead to that document, and your colleague needs permission to open it. A finished-looking handout doesn’t tell you whether either happened.

The mistake is treating a convenient clue as proof of the result you wanted. That stand-in is called a **proxy**. File creation is useful evidence of progress. It just cannot, by itself, answer a different question about someone else’s access.

Think of “Be Kind, Rewind” on a VHS case. Excellent advice. Tragically incapable of rewinding the tape. A label can describe the finish line without getting you there.

The same distinction matters with an AI assistant: it may have done real, useful work, while its evidence covers only part of your request. Asking it to sound more certain won’t check the missing part.

Try naming the result before work begins: “My teammate needs to open this exact handout using our existing access. Tell me what you checked and what still needs checking.” Then check the link with an intended recipient. Keep private documents private; making a link public is not the fix.

You don’t need a launch ceremony for every shopping list. Match the check to what you’ll rely on. If you only asked for a draft, seeing that draft may be enough. If other people need to use it, check that they can.

A small question to keep: **what would show me the result I actually need?**
