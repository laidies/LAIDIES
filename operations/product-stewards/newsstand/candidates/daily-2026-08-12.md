# THE DAILY — August 12, 2026

## The hidden text in an AI log may not be harmless

**The short version:** A new research paper reports that encrypted reasoning blocks used by some AI APIs could be replayed into a compatible model and turned back into readable text. The researchers found personal information and credentials inside blocks people had posted in public repositories. They disclosed the method before publication and say the providers then stopped the same attacks from working.

This is a real security finding. It is not evidence that every ChatGPT or Claude conversation you have ever shared can suddenly be opened like a diary.

### What actually happened

Some developer tools use reasoning models that generate working text before the final answer. The full working trace is not normally shown to the person using the tool. To let an application continue the same task later, an AI provider may return that trace as an opaque encrypted block. The application holds the block and sends it back on the next request.

The paper's authors found that, in the API versions they tested, those blocks travelled too freely: a block created in one context could be handed to another compatible model from the same provider family. A weaker model could sometimes be prompted to reproduce the hidden text.

The important distinction is not “encryption failed.” The researchers did not report stealing an encryption key. The system accepted a valid sealed block in a context where it should not have been useful. A sealed hotel keycard can be unreadable to you and still be dangerous if it opens more rooms than intended.

The researchers collected 315,320 reasoning blocks from public repositories. They classified 367 pieces of personally identifying information and 182 credentials, including API keys and passwords. Those are the researchers' reported totals from a targeted scan, not proof that every public AI log contains a secret. They also say they could not compare every recovered word with a ground-truth plaintext trace.

### What you should do

If you publish or share raw API responses, coding-agent transcripts or agent logs, remove opaque reasoning or signature fields as well as visible secrets. If one of those records has already been public, treat any credential that may have entered the session as exposed: revoke or rotate it and check the provider's current guidance. Sanitizing only the readable text is not enough when an unreadable field can carry session content.

At work, that means a team should not commit raw agent logs to a shared repository simply because the obvious prompt and answer look clean. At home, it does **not** mean you should panic about an ordinary shared-chat link on the basis of this paper alone. The demonstrated risk concerns raw developer/API records containing compatible reasoning blocks.

**The line to keep:** unreadable to you is not the same as safely scoped by the system.

**Sources:** [Panfilov et al., “Stealing Reasoning Traces from Proprietary LLM APIs”](https://arxiv.org/html/2608.09867) and its [versioned arXiv record](https://arxiv.org/abs/2608.09867).

## OpenAI opens two approval lanes for cyber work

OpenAI introduced two approval-based cyber-access lanes on August 10. **Daybreak Blue** is for approved defensive work using general-purpose models. **Daybreak Red** is a separate approval for higher-risk authorized work and may include a purpose-built model called GPT-5.6 Cyber.

OpenAI's current material does not establish a public plan, price, region or automatic path from Blue to Red. It describes access that can be limited by identity, organization, project, model and product surface.

Why split access at all? A model that can help a security team reproduce and fix a serious vulnerability can also make harmful cyber work easier. OpenAI says Red work requires tighter scope and controls, including an isolated environment, least privilege and review. Those are the company's stated controls, not independent proof that every approved engagement will be safe.

If your organization is considering Daybreak, start with a named authorized project and a responsible security owner, then check the current criteria before assuming that either lane is available.

Outside work, use this as a quick test whenever a specialist AI model appears in your feed: open the official access page and ask whether it is a public product release, an approval program or a research preview. A new model can be real without being something you can—or need to—select in an everyday AI app.

**Bottom line:** “new model” and “new model available to everyone” are different stories.

**Sources:** [OpenAI Daybreak](https://openai.com/daybreak/), [OpenAI's trusted-access overview](https://help.openai.com/en/articles/20001258-openai-daybreak-trusted-access-for-cyber-overview) and [OpenAI's cyber-safety guidance](https://learn.chatgpt.com/docs/cyber-safety).
