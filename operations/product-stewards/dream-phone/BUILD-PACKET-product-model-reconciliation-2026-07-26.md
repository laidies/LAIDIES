## Required mechanics and evidence

Every surviving learning direction must prove:

1. meaningful choice before the answer;
2. consequence that changes the player's information or next move;
3. clause-level, source-bounded feedback;
4. replay that practises transfer rather than answer memory;
5. a representative unfamiliar player can explain the judgment and name
   evidence that would change it;
6. exact source admission, freshness, correction and fail-closed behaviour.

Every surviving reflection/advice direction must prove:

1. scripted/general boundary before reliance;
2. role-specific output and useful next move;
3. no sensitive free-text collection;
4. consequential topics route or stop safely;
5. reload, repeat, missing data and third-party failure stay honest.

## Visitor-state acceptance suite

- First visit → first meaningful result → exit.
- Leave → return without Resident Card.
- First/returning → create local Card → same-device return.
- Storage denied, corrupt and partially written.
- Signed-in/sign-out/second-tab/second-device only if selected intent supports
  account state.
- Deep-link arrival and honest fallback.
- Local/account conflict with explicit merge/replace/fail-safe only if needed.
- Card/account deletion or reward revoke propagated to every consumer only if
  durable Dream Phone objects are selected.

For each: 390/430 mobile, 1440 desktop, keyboard, screen reader, reduced
motion, 200% zoom/reflow, empty/loading/error/retry/duplicate/offline, and
privacy-safe analytics outcome.

## Source/content operation

- Current claim ledger remains the only admission control for the bounded beta
  until superseded by an approved model.
- Primary/official sources are required for playable factual claims where
  available; secondary sources remain discovery/HOLD.
- Every clause has exact text, source URL, source limit, checked date,
  `reviewBy`, correction state and independent reviewer.
- Changed/corrected/stale content is removed from play automatically and cannot
  be restored without re-admission.
- Content cadence must name owner capacity; no weekly promise without a
  sustainable review operation.

## State, rewards and analytics

- Default baseline is session-only, anonymous and no account promise.
- If durable state is selected, the packet must name authoritative producer,
  schema/event, identity scope, idempotency, pending/saved/failed UI,
  migration, restore, duplicate handling, delete/revoke, second-device
  consumer and rollback.
- No reward may substitute for learning or utility.
- Minimum privacy-safe events: entry/status viewed, direction/mode selected,
  first meaningful action, result, evidence action, feedback, replay, exit and
  coded failure. Never send free-text problems, answers, member email or
  identifying source URLs.
- Pageviews, recordings and correctness alone do not prove value or learning.

## Release gate and rollback

No release claim until:

- owner decision and Council winner exist;
- product, trust and brand floors pass independently;
- full visitor/accessibility/failure suite passes;
- every intended producer/consumer path is authoritative;
- exact candidate identity is bound to the release;
- public route and entry-point copy are verified.

Rollback must restore the last verified public artifact, remove misleading
entry promotion, and fail held evidence/reward capabilities closed without
destroying user state. A rollback is a safety action, not a product-model
decision.

## Measurement and freshness

- First useful-result completion and comprehension.
- Transfer evidence for unfamiliar players where educational.
- Boundary comprehension and usefulness where reflective.
- Failure/retry rate, evidence-source opens as supporting—not outcome—signal.
- Weekly claim/correction triage while any factual deck is public.
- Monthly accessibility/journey review.
- Triggered re-entry after model, content, platform, public route or owner
  decision changes.
