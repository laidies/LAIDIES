# Study Pack candidate admission gate

**Status:** LOCKED — MANDATORY BEFORE ANY STUDY PACK VISUAL IS SHOWN TO ALI  
**Owners:** Learning System & Concepts + Blend & Snap + affected component owner  
**Applies to:** sketches, HTML visualizations, screenshots, image generations,
printables, PDFs, card previews, prototypes and “quick samples,” including
private or local work

## Why this gate exists

On 2026-07-27 an Episode 01 Study Pack visualization reached Ali even though it
was a sterile placeholder, contradicted the episode visual world, exposed
internal job labels as visitor navigation, used a banned word, made the
relationship between components unclear and represented a Trading Card pack as
one coloured rectangle. Ali had to perform basic product, language and visual
QA on work that should have been rejected internally.

That output is **REJECTED EVIDENCE**. It is not a base to reskin, refine or
propagate.

## Gate 0 — authority and production permission

Before making a visual candidate, record:

- the exact episode canon and source checksum;
- the current Brand/visual ruling and the visual work it permits;
- the affected product/component owner;
- the approved episode and style reference paths;
- the one variable the comparison is allowed to change; and
- the fixed product/content invariants every option must preserve.

If a current lock permits inventory/specification only, stop. A private mock,
HTML visualization or generated “sample” is still visual production and does
not bypass the lock.

## Gate 1 — use the real product names

The Study Pack contains only the selected, admitted components. Episode 01 has
three:

1. **Cheat Sheet**
2. **Try-On**
3. **Trading Card Pack**

A later episode may include a **Study Sheet** or another named component only
when the intake record proves a distinct learner job. A template slot is not a
reason to make another item.

The **Pop Quiz at SUNNYVAiLE High** is coordinated beside the Study Pack but is
not inside it.

Internal cognitive-job words must not become visitor-facing tabs, tickets,
navigation or component names. In particular, do not label the pack
`REVIEW`, `PRACTISE`, `REMEMBER`, `KEEP` or `CHECK`.

The word `rep` is banned from current LAiDIES copy, labels, briefs and
candidates. Use the precise intended action: `first try`, `practice task`,
`attempt`, `comparison`, `test` or another plain-language description that
actually fits.

Before rendering, run a case-insensitive whole-word terminology scan on all
candidate copy. A match for `rep`, or an unexplained internal label, is a
blocking failure.

## Gate 2 — cold-reader comprehension

A person who did not write the artifact must be able to answer these questions
from the actual rendered candidate in five seconds:

1. What is this?
2. How does it connect to Episode 01?
3. What is included in this Study Pack?
4. What does each item help me do?
5. What should I open first?
6. Which items can I print or download?
7. Where is the Pop Quiz, and why is it separate?

If the reviewer needs an explanation from the maker, the candidate fails. A
caption below a confusing diagram does not repair the diagram.

## Gate 3 — visual fidelity

The maker and an independent visual reviewer compare the full render with the
actual approved references, not with the prompt or CSS:

For the Episode 01 Study Pack, Ali approved the page style on 2026-07-28:
Homepage-level soft pink–lilac–cyan gradient plus brighter, same-family
colour-block cards following the visible **LAiDIES Method** and **Games and
tools, open all day** examples. Editable fields stay neutral. This positive
reference now governs new components and revisions.

- Episode visual-world match;
- adult LAiDIES craft and correct 1990s colour register;
- no candy palette, sterile white-box dashboard or generic SaaS grammar;
- no black or near-black interface background;
- no cream/paper editorial theme;
- no white-and-deep-plum page theme;
- no candy hue used as body text, text-input fill, text-input border or
  explanatory-box accent;
- no automatic uppercase treatment may rewrite `LAiDIES`, `SUNNYVAiLE` or
  another authored lower-case `i` brand name;
- every saturated fill or selected state must declare and verify its own
  foreground colour; a global white- or dark-text rule is not sufficient;
- the actual episode imagery carries the principal colour and atmosphere, with
  saturated colour reserved for a few decisive interaction states;
- clear information hierarchy and relationship cues;
- no unexplained dead space, severely unbalanced columns or display heading
  forced into a narrow track while an adjacent track remains materially empty;
- every changed parent grid must be checked with its real descendant content
  at the final desktop and mobile widths, including heading wrap, image scale
  and section-height balance;
- real, legible component previews rather than placeholder blocks;
- no invented town/product language; and
- no decorative visual that obscures the learner action.

“Polished,” “functional,” “responsive” and “valid HTML” are not substitutes
for belonging to LAiDIES.

### Blocking LAiDIES wordmark check

For current web and interactive Study Pack work, the authority is the live
homepage wordmark: Jost 800, `L` + accented `Ai` + `DIES`, with the separately
positioned i-dot. Pull the markup and metrics from the current homepage or
`content/site/sv-topbar.css`; do not select a logo by browsing an asset folder.

The following older raster/SVG wordmarks are **RETIRED FOR CURRENT WEB USE**,
even when a copy remains under `approved-assets` for historical evidence or an
older bound production:

- `laidies-wordmark-final-b-light.*`
- `laidies-wordmark-final-b-dark.*`
- `laidies-logo-header-approved-v6.png`
- `laidies-logo-masthead-approved-v3.png`

Any current Study Pack candidate containing or referencing one of those assets
is an automatic **REJECT — DO NOT SHOW ALI**. Cropping, recolouring, filtering
or placing the retired mark on a new background does not make it current.
Before rendering, run an exact filename/reference scan and compare the visible
wordmark against the current homepage at the same scale.

## Gate 4 — Trading Card truth

A Trading Card Pack preview must look and behave like a pack of cards:

- a visible pack/deck identity;
- multiple cards or an unmistakable collection;
- image or word retrieval cue on the front;
- short explanation on the back;
- episode/pack/card numbering;
- a print sheet or truthful print status;
- a non-motion way to inspect both sides; and
- exact Trading Cards owner/rights/platform status.

A flat rectangle containing a card description, placeholder art instruction or
“flip” button is not a Trading Card candidate. Reject it before review.

For Episode 01, the visual direction uses the saved 1990s card references and
Ali’s specified pop palette: purples, vibrant pinks, electric/cobalt blues and
sunshine yellow. The colour must come through the authored card art, pack
identity and decisive interaction moments. It must not become a candy palette,
a black-background interface, a cream/paper editorial treatment, a
white-and-deep-plum page, or pastel/candy text-box decoration.

### Episode pack identity

The **card anatomy stays consistent across episodes**, but the **entire pack
identity changes with the episode**. Each episode requires its own
episode-art-led:

- pack background colourway;
- two or three decisive accent colours;
- wrapper/cover treatment;
- back-frame colourway and comic accent;
- selector/current-card treatment; and
- print-sheet identity.

Do not recolour individual cards randomly within one pack. One episode should
read as one coordinated collection. Do not copy Episode 01's pink/purple/blue/
yellow pack treatment into Episode 02 or later packs by default. Before making
the next pack, extract the palette and graphic cues from that episode's
approved art, record them in the component brief, and compare the rendered pack
against both the common trading-card anatomy and the episode-specific source.

## Gate 5 — print and download proof

Anything described as downloadable or printable requires actual evidence:

- a working download/print action in the candidate;
- exact US Letter and A4 renders;
- readable type at print size;
- safe margins, correct page count and no clipping;
- sensible ink use without destroying the visual identity;
- front/back card alignment where applicable;
- source checksum, renderer/version and output checksum; and
- print reading order and accessibility check.

“Designed to be printable later” is not printable.

## Gate 6 — do-not-show-Ali verdict

The maker and an independent reviewer each record `PASS` or `REJECT` for:

| Gate | Required result |
|---|---|
| Authority/lock | PASS |
| Episode/canon fidelity | PASS |
| Real component names and banned-language scan | PASS |
| Cold-reader comprehension | PASS |
| Visual/reference match | PASS |
| Trading Card truth, if shown | PASS |
| Letter/A4 proof for printable claims | PASS |
| Desktop/mobile proof for interactive claims | PASS |
| No P0/P1 defects | PASS |

Any failure produces **REJECT — DO NOT SHOW ALI**. The work may be retained as
failure evidence, but it cannot be presented as an option, sample, direction or
owner decision.

Ali is asked to choose only between internally admitted, materially distinct
candidates. She is never asked to identify that a placeholder is confusing,
off-brand, incorrectly named or not the promised product.
