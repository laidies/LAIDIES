### Suggested title

# A Draft File Is Not a Launch Party

### Suggested deck

The four different meanings of “done” that AI keeps collapsing—and the one
status prompt that stops it.

### Field Note draft

An AI agent can say “done” with Cher Horowitz leaving the mall confidence while
the thing is still in the fitting room with the tags on.

I learned this while checking the status of a LAiDIES episode. Our status tool
found a draft file and confidently reported that the episode had already gone
out.

It had not.

The file existed. That was the only fact the check had actually proved.

This is a **proxy problem**: you measure something convenient that seems
related to the answer you want, then accidentally report it as the answer
itself. A file on a computer can prove that somebody created a file. It cannot
prove that a human approved it, that the right version was deployed, or that a
reader can open it and use it.

So we stopped using “done” as one giant mystery status and split it into four:

1. **Authored** — the current draft exists.
2. **Approved** — the named decision-maker approved that exact version.
3. **Deployed** — that version was released to the intended destination.
4. **Publicly verified** — someone opened the real public link in a clean
   browser state and completed the promised action.

Each state needs its own receipt. An earlier state cannot stand in for a later
one. The draft is not the launch. The deploy command is not the working public
journey. And “it should be there” is not a smoke test.

### The prompt you can steal

> When you report this task’s status, separate **authored, approved, deployed
> and publicly verified**. For each state, show the specific evidence you
> checked. If there is no evidence, report that state as unknown or incomplete.
> Do not infer a later state from an earlier one.

### Why this works

It makes the AI answer four small evidence questions instead of one fuzzy
question. That gives it fewer opportunities to substitute a plausible clue for
the state you actually meant.

Not every task needs to be deployed publicly. The useful move is to define the
real finish line for *your* task—and require evidence for that state instead of
letting “done” wear four outfits at once.

**Try this today:** Ask your AI to re-report one current project using distinct
states and one receipt per state. If it cannot show the receipt, you have found
the next thing to verify.
