# Masterclass Lesson 4 — From Chatting to Working

**Status:** BUILT LOCALLY — instructional content candidate; not independently
accepted, filmed, admitted or public.

## Learner and objective

**Learner:** A woman who already uses conversational AI naturally and has one
safe, ongoing job that matters enough to organize.

**Prerequisite:** She can open a conversational AI product and understands
that the product/tool and the model are different layers.

**Observable objective:** Given a changing assignment, the learner can:

1. use conversation to discover the job;
2. consolidate the current objective, sources, decisions, constraints and
   finish line into a working brief;
3. choose let-finish, queue, steer or stop based on consequence;
4. choose the same session, new session, clean review, branch or Project based
   on objective and authority; and
5. save an artifact/status/handoff that lets work resume without reconstructing
   the assignment from scattered messages.

## Correct mental model

A chat is a working session, not automatically the whole project or its source
of truth.

- **Conversation** is useful for discovery, questions, examples and ordinary
  revision.
- **The working brief** states the current assignment after discovery.
- **A session/chat** owns one coherent objective or bounded workstream.
- **A Project or project-like workspace** is a scoped home for an ongoing body
  of work, shared instructions and selected sources.
- **A working mode** changes what the tool will do next: conversational help
  versus longer multi-step execution.
- **A turn or intervention** changes, queues, questions or stops the current
  work.
- **The artifact/status record** is the durable approved result and current
  state.

Long context, memory and retrieval can make prior information available. They
do not establish which objective, decision or version is authoritative.

## Adjacent distinctions

- A complete brief is not the same as one giant perfect prompt.
- A new chat is not automatically a blank slate.
- A Project is not the same as a chat or a broad company/account workspace.
- Work/Cowork/agent mode is not simply a smarter model.
- Branching preserves an alternative line; it does not create a second source
  of truth.
- A question can materially steer or stop work if its answer changes whether
  the current result is valid.

## Instructional sequence

1. **Recognize the trap:** one thread is simultaneously idea inbox, brief,
   workbench, review and completion record.
2. **Use natural discovery:** allow a normal back-and-forth to reveal the real
   job.
3. **Pause and brief:** consolidate the current governing assignment before
   substantial execution.
4. **Execute in bounded stages:** keep the same session while objective and
   artifact remain coherent.
5. **Intervene by consequence:** let finish, queue, steer or stop.
6. **Choose the boundary:** stay, start fresh, open a clean review, branch or
   create/use a Project.
7. **Checkpoint:** save artifact, decisions, status and next action outside the
   conversation transcript.
8. **Transfer:** classify six new scenarios and explain the governing
   boundary.

## Controlled demonstration

Use one fictional job:

> Prepare the sign-up email and event-day run sheet for a neighbourhood
> clothing swap.

The facts arrive naturally:

- audience includes women who are not comfortable with apps;
- registration must work by email or phone;
- venue is step-free;
- budget is $200;
- do not collect clothing sizes;
- volunteers have only two hours for setup;
- outputs are one sign-up email and one timed run sheet;
- completion means both outputs use the approved facts and identify remaining
  decisions.

### Before

Show the information arriving across a natural conversation after an early
draft already exists. The early app-based registration assumption persists
under later corrections. This is a pre-authored fictional sandbox, not a live
uncontrolled failure.

### One changed variable

Pause and create a current working brief containing exactly the same facts.
Nothing else changes: same tool, task, sources and desired outputs.

### After

Execute the email and run sheet from the current brief in two bounded stages.
Check both outputs against the same finish line. Save the accepted versions,
status and next action.

**Mechanism:** The model no longer has to infer which scattered message is the
current authority. The tool supplies one consolidated assignment for the
stage.

## Live-work decision practice

While the bounded task runs, classify four new messages:

1. **Queue:** “After this, turn the approved email into a poster.”
2. **Steer now:** “Use the venue's approved accessibility wording, not a
   paraphrase.”
3. **Stop:** “The event is for vendors, not neighbours. Do not continue with
   the current audience.”
4. **Let finish / do not send yet:** “Why did you choose that heading?” when
   the answer will not change the current deliverable.

The rule is consequence, not punctuation.

## Transfer scenarios and rubric

The learner chooses an action and explains why:

1. Same report, ordinary wording revision → **stay in the same session**.
2. Independent accuracy review of the completed report → **clean review
   session with original brief and candidate artifact**.
3. Alternative campaign direction that must not overwrite the main line →
   **branch or separate bounded session**.
4. Unrelated personal task inside a company Project → **separate Project or
   correct broad workspace/account boundary**.
5. Ongoing campaign with shared sources and research/draft/review workstreams →
   **one Project with purposeful sessions**.
6. Current run is using the wrong confidential file → **stop immediately,
   inspect partial state and restart from the corrected brief**.

A passing explanation names the governing objective, source/permission
boundary or review independence—not merely the product button.

## Misconceptions to resist

- Natural conversation is bad.
- One enormous prompt is the professional answer.
- Every follow-up weakens the result.
- Every new thought must interrupt current work.
- A long context window keeps every old decision active.
- A new chat automatically fixes a bad brief.
- A Project reconciles contradictions or makes every file authoritative.

## Analogy and limit

The instant-message window is where the conversation happens. The production
binder holds the assignment, approved decisions and current version.

**Limit:** Human friends may remember shared history and social implication in
ways an AI product does not. A product may also carry memory, retrieval or
Project context into a new session, so a new window does not always mean a
total stranger.

## Modality advantage

The class must show state changing over time: an early draft, accumulating
corrections, the pause into a current brief, bounded execution, live
intervention choices and a durable checkpoint. Animation and screen
demonstration make the invisible authority shift visible; practice proves the
learner can act on it.
