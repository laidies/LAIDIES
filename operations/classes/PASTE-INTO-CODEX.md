## 1. What LAiDIES is
LAiDIES teaches AI to smart women who were not invited into the tech conversation. It is not a
blog and not a course-in-the-syllabus sense. It is a **town — SUNNYVAiLE — permanently set in
1999**: a weekly episode, a radio station, a high school, a library, characters, collectibles.
The reader returns to a place; she does not read an article once. Brand = **LAiDIES**; town =
**SUNNYVAiLE**. Tagline: *girl power meets machine power.*

**SUNNYVAiLE High** is where the how-to-actually-use-the-tools video classes live. A class is a
short screen-recording with voiceover and a title card — watch it done on the real screen. (The
LIBRAiRY is the reference-book side; episodes are the story/thinking side. Classes are the
show-me-where-to-click side.)

## 2. The reader
A busy, intelligent woman, **no computer-science background**, learns by analogy and image. New
to this one subject, not to competence — she runs things, manages people, has judgment. The two
failure modes: **talking down to her**, and **assuming she already knows the jargon.**

## 3. Voice rules (these are locked)
- **1999, always.** No "nowadays", no "the future", no dating the outside world. Modern software
  is allowed to exist — it lives *inside a television* in the fiction.
- **Insider humour, not nostalgia-bait** — AIM away messages, Seventeen quizzes, Trapper
  Keepers, gel pens, mixtapes, butterfly clips, Delia*s, Blockbuster, the chick-flick canon. The
  joke lands **on the AI point**, never on the reader.
- Two cringes to catch: influencer-hustle ("STOP SCROLLING", "link in bio") and tech-bro
  ("disrupt", "10x", "ship it", "hot take"). Heuristic: **if a man in a quarter-zip would post
  it, it is wrong.**
- **AI is "it"**, never "she". It does not think/want/understand/remember in the human sense —
  say what it mechanically does: stores, re-reads, produces, fills in.
- "AI" is always both capitals. Lowercase `Ai` appears ONLY inside brand words (LAiDIES,
  SUNNYVAiLE, LIBRAiRY).
- ⛔ Banned phrasing: "the whole point" / "that's the whole [x]"; "the X nobody Y" and any
  false-exclusivity hook ("nobody teaches this"); revolutionary, game-changing, unlock,
  seamless, effortless, supercharge. No emoji in narration. No exclamation marks in narration.

## 4. Teaching rules (locked)
- **Plain teaching carries; the analogy garnishes.** Write the explanation exactly as plainly as
  you would say it to a smart friend. If the plain version is clearer than the analogy version,
  the analogy is in the way. The analogy decorates a clear idea; it never carries one.
- **Show, do not lecture. Never "teach conceptually."** Every building block is taught with a
  concrete, shown example — not an abstract definition. If a class is all definition and no
  demonstration, it has failed.
- **Two nouns, always distinguished: THE TOOL and THE MODEL.**
  - *the model* — the part that produces the words; has a cutoff; does not know you.
  - *the tool* — everything built around it: the account, memory, settings, files, connectors,
    modes, the buttons.
  Memory belongs to the tool, not the model. If these blur, the reader thinks the thing that
  writes is the thing that remembers her, and nothing lands.
- **Every class carries a Before & After: bad take → why it did that → the fix → good take, with
  EXACTLY ONE variable changed** between bad and good. If more than one thing changes, it teaches
  "longer is better" instead of teaching the cause. The "why" is the mechanism in one plain
  sentence, drawn from one of four: (1) nothing narrowed it so you got the average; (2) it will
  not stop and ask; (3) it only sees what is in front of it; (4) plausible is cheap.
- **Analogies must be grounded in the town's own 90s/Y2K canon** (the "Mall" — SUNNYVAiLE's
  inventory of cultural/shopping references). Free-floating analogies are not allowed; if one is
  needed and not yet in the town, the answer is "add it to the Mall". TWO analogies are already
  locked canon and must be used as written, not redesigned:
  - **Memory / context → the Blend & Snap** (the town café): a brand-new café cannot give you
    "the usual" — it has never met you, so you spell out the order every time; your regular spot
    can, because you built that over a hundred Tuesdays.
  - **Models / versions / cutoffs → textbook editions**: once printed the words cannot change;
    the cutoff is the print date; web search is the teacher's photocopied handout.

## 5. THE STRUCTURE UNDER REVIEW — this is the main thing to evaluate

**The problem being solved:** if each tool subject teaches "what memory is" from scratch, the
reader hears the same explanation three times (ChatGPT, Claude, Gemini). Wasteful and dull.

**The proposed fix — a two-layer curriculum:**

| Layer | Teaches | Example |
|---|---|---|
| **THE BASICS** (cross-tool, taught once) | **What each building block IS**, and why it matters — with a concrete shown example. The fundamentals that are the same in every tool. | "What memory is: the tool keeps a note about you, separate from your chats. Here it is making the same request land differently." |
| **THE TOOL SUBJECTS** (ChatGPT, Claude, Gemini) | **How to actually use that building block in THAT tool** — where it lives, how to set it up, the one trap specific to it. | "Memory in ChatGPT: Settings → Memory. Here is the screen, here is how you edit an entry." |

So a reader learns *what memory is* once, then visits her tool to learn *where memory lives*.
The building blocks are the shared vocabulary; the tool subjects are the tours.

**The candidate framing analogy for "same blocks, different tools" (needs evaluation — pick the
better one, or propose a stronger canon-grounded option):**
- **(A) Mall fixtures.** Every store in the mall has the same fixtures — a fitting room, a
  register, a sale rack, a returns desk. Each store lays them out and styles them its own way,
  but the fixtures do the same job everywhere. Learn what the fixtures are and you can shop any
  store. ChatGPT, Claude and Gemini are different stores; memory, skills, connectors are the
  fixtures they all have.
- **(B) Dress code** (Ali's first instinct, flagged by her as probably not great). The dress
  code is basically the same; how each one chooses to dress for it differs.

## 7. TWO WORKED EXAMPLES (evaluate example quality — is exactly ONE variable changing?)

### Example 1 — MEMORY (Basics)
- **Variable that changes:** whether the tool is carrying a note about you.
- **Task:** the identical eight-word request, typed twice, minutes apart. Wording never changes.
- **Bad:** On an account that knows nothing about you, type *"Write a note to my team about the
  delay."* → *"Dear Team, I wanted to take a moment to reach out regarding the recent delay..."*
  — bland, generic, could be anyone's.
- **Why (the mechanism):** It was handed eight words and nothing else, so it filled every gap
  with the most likely guess — a generic team, a generic delay, a generic voice. It did not stop
  to ask which team, because it does not stop and ask.
- **Fix:** Not a longer prompt. A filled-in memory — who you are, what you run, that you write
  short. Set once.
- **Good:** The identical eight words, on the account that has your note → *"Team — the supplier
  missed Friday, so the report lands Wednesday. Nothing else moves. Shout today if that breaks
  something your end."*
- **Verdict line:** Same eight words, same tool, same minute. The only thing different was the
  note the tool was already holding.

### Example 2 — CONTEXT (Basics)
- **Variable that changes:** whether your earlier instruction is still close enough to be read.
- **Task:** the same request, made twice — once early in a chat, once forty messages later. The
  words of the request never change.
- **Bad:** At message 41, *"Give me three options for the headline."* → three headlines, all with
  exclamation marks, all long. At message 3 you had said: under eight words, never an exclamation
  mark.
- **Why (the mechanism):** It can only work from what fits in front of it at once, and the
  conversation stopped fitting a while ago. Your rule from message 3 is no longer in the room. It
  is not ignoring the instruction — it cannot see it.
- **Fix:** Not repeating yourself louder. Start fresh with the rule at the top, or put the rule
  somewhere permanent (personalization) so it never competes for space.
- **Good:** Fresh chat, rule at the top, same request → three short headlines, no exclamation
  marks.
- **Verdict line:** Identical request. The rule was simply close enough to be read.
