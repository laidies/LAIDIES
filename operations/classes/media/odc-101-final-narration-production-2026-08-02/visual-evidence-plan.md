# ODC-101 visual evidence plan

Status: **PRODUCTION PLAN / PICTURE HOLD UNTIL NARRATION LOCK**

This plan applies the canonical class-media standard to the final ODC-101
picture. The approved narration clock controls final occurrence timing. Every
real-interface capture uses a non-personal fixture and records product,
platform, account/plan boundary, capture date and source evidence.

| Scene | Teaching job | Required visual | Freshness boundary |
|---|---|---|---|
| 01 · Title | Promise the useful mental map | Branded title plus a restrained app → model → context → tool → judgement motif | Durable; no product UI |
| 02 · Four layers | Separate product layers | Purpose-built animated layer diagram, revealed in narration order | Durable unless the conceptual model changes |
| 03 · App | Prove similar models can sit inside different products | Current, labelled screenshots of real product shells using neutral fixture accounts; highlight interface/account/settings boundaries | Replace individual screenshots when the visible products change |
| 04 · Model | Locate the model inside the product without personifying it | Stable diagram showing the model as one component, not a talking robot or magic brain | Durable unless the explanation changes |
| 05 · Working context | Show what enters one task and what stays out | Animated context tray using fictional files, instructions, history/memory and tool results; visibly exclude a mock private file | Durable concept; any real product example is a separate insert |
| 06 · Search | Show how current evidence enters the job | Short real screen recording of the current search control and one source opening, with exact product/platform/plan/date label | Volatile current-path insert; replace without rerecording durable narration when only location/label changes |
| 07 · Worked example | Compare unsupported fluency with evidence-backed work | Real screen recording using a fictional reimbursement policy fixture: same question, then one-variable change adding the operative notice/search result; hold the effective-date sentence and remaining uncertainty | Fixture is durable; product chrome/path is replaceable |
| 08 · Citation check | Teach the three-question source check | Zoomed screenshot/result pair with callouts on date, exact supporting sentence and responsible source; no decorative citation icon alone | Replace cited product UI independently; decision rule is durable |
| 09 · Task map | Move from watching to doing | Interactive Try-On map the learner completes: output, context, optional tool, check and private-data boundary | Durable learner interaction |
| 10 · Explain-back | Retrieve and transfer the idea | Quiet prompt with optional reveal of a strong answer; no unrelated animation while the learner thinks | Durable learner interaction |

## Capture rules

- Record product navigation slowly enough to repeat at 1×. Signal the target
  before clicking and hold the result long enough to inspect.
- Use screenshots when one stable state is sufficient; use screen recording
  only when sequence or state change is part of the lesson.
- Do not narrate a brittle route such as “click the third icon on the left” in
  the durable track. Put current labels and paths in the replaceable insert.
- No personal accounts, notifications, real workplace material, private
  memory, browser history or unrelated tabs may appear.
- The reviewer describes what is visible at every occurrence and decides
  whether it explains the narration at that time. A merely attractive image is
  not close enough for a procedural teaching job.

## Freshness response

- Menu location/label changed: replace scene 03, 06, 07 or 08 insert as
  applicable; recheck its captions, transcript fragment and search metadata.
- Capability/access/privacy/workflow changed: reopen the source claim,
  narration, practice and all related occurrences.
- Capture cannot be reproduced safely: hold the affected path; do not preserve
  an obsolete walkthrough for visual continuity.
