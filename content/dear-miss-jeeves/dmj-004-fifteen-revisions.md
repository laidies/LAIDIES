# Dear Miss Jeeves, why does the output sometimes get worse after fifteen revisions?

Dear Exhausted,

Because revision fifteen is often being asked to repair revision fourteen—not to satisfy the whole original job.

Each correction can become a local note: keep this paragraph, lose that tone, make the title brighter, restore the fact you dropped. If you judge only the next answer, the latest complaint gets attention while an earlier requirement quietly falls out. Long sessions can also amplify repeated or competing prompt material. The result may be more obedient to your most recent sentence and less faithful to the thing you were trying to make.

And the apology is not a control. An AI can produce “You’re right; I’ll follow that rule” because an acknowledgement fits the conversation. That sentence does not install a lock, update a test or prove the next output complied. It is a promise-shaped output, not a receipt.

## What people commonly misunderstand

More instructions do not automatically create more control. A rule file can help, but only if the workflow loads the current file and something checks the result against it. Starting a new session can reduce clutter, but it can also discard useful decisions and is absurd as the universal prescription for a long job. You should not have to move house every time one cupboard becomes untidy.

## Miss Jeeves prescribes

1. **Keep one whole-job brief outside the conversation—and reconcile it.** Record the audience, purpose, non-negotiable requirements, prohibited changes and what “done” means. When feedback changes a requirement, replace the old instruction and mark it superseded; do not paste a fifteenth rule beside fourteen conflicting ones. This brief is the authority; chat history is supporting material.
2. **Protect the last genuinely good version.** Give it a version number. A new draft is a candidate, not an automatic replacement.
3. **Make a small rerunnable test set.** For a board briefing, use the same fictional source packets and check that three required facts, the audience, the length and the no-invented-quote rule survive. At home, test the same imaginary itinerary days and check mobility needs, meal times and budget.
4. **Change one thing at a time.** Then rerun every check, including the old ones. If the new version fixes the title but drops a fact, it has not improved.
5. **Use checkpoints and bounded handoffs for long work.** Save decisions, progress and accepted artifacts somewhere durable. If a fresh context is useful, hand it the current brief, accepted version and open issue; do not ask it to reconstruct the project from memory.

## When it is not your fault

Sometimes the limit belongs to the product or workflow: the available context, missing attachments, unavailable tools, permissions, an outage or a model change. Some requirements also need deterministic code or a validator, not another beautifully worded plea. If the same stable test keeps failing, stop revising the prompt. Change the workflow, split the task, try an appropriate tool or take over the consequential step yourself.

Please stop pinning another Post-it to the same overstuffed Trapper Keeper and calling it quality control. Preserve the truth, test the candidate and make revision sixteen earn the keys.
